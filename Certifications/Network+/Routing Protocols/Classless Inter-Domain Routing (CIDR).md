CIDR is a method for allocating [[Internet Protocol Suite (TCP IP)#Internet Protocol (IP)|IP]] addresses for IP routing. The goal of implementing CIDR was to slow the growth of routing tables on routers across the Internet, and to help slow the rapid exhaustion of IPv4 addresses.

IP addresses are described as consisting of two groups of bits in he address: he mos significan bits are the network prefix, which identifies a whole network or [[Subnet]], and the least significant set forms the host identifier, which specifies a particular interface of a host on that network. This division is used as the basis of traffic routing between IP networks and for address allocations policies.

Whereas classful network design for [[Internet Protocol Suite (TCP IP)#IPv4|IPv4]] sized the network prefix as one or more 8-bit groups, resulting in blocks of Class A, B, or C addresses, under CIDR address space is allocated to Internet Service providers and end users on any address-bit boundary. In [[Internet Protocol Suite (TCP IP)#IPv6|IPv6]] however, the interface identifier has a fixed size of 64 bits by convention, and smaller subnets are never allocated to end users.

CIDR is based on Variable Length Subnet Masks (VLSM), in which network prefixes have variable length. The main benefit of this is that it grants finer control of the sizes of subnets allocated to organizations, hence slowing the exhaustion of IPv4 addresses from allocating larger subnets than needed. CIDR gave rise to a new way of writing IP addresses known as CIDR notation, i.e. 192.0.2.0/24 for IPv4 and 2001:db8::/32 for IPv6.
